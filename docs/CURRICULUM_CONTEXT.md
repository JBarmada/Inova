# Curriculum Context

The team supplied SCOPE curriculum lessons 1, 2, 3, 4, 5, and 7 new. The connections below summarize their inspected slide text. They explain possible applications of the curriculum; they are not a final-project rubric or a requirement to use the example stack.

## Concepts relevant to Inova

| Lesson | Material | Possible Inova application |
| --- | --- | --- |
| 1 | LLM basics, limitations, verification; especially slides 28–30 | Do not invent commitments or treat confident model claims as verified facts |
| 2 | APIs, conversation context, structured output, and agents; especially slides 29–33 | Produce usable quest objects and let a model request narrow capabilities |
| 3 | Prompt evaluation and iteration; slides 2–9 and 26–28 | Compare prompts against the same representative student situations |
| 4 | Function calls, authoritative records, validation, bounded loops, errors, and traces; slides 13–28 | Ground suggestions, validate tool arguments, return structured errors, and stop predictably |
| 5 | Retrieval, chunking, embeddings, lexical/semantic search, grounding; slides 3–4, 17, and 38 | Retrieve relevant approved memories without sending an entire journal |
| 7 | End-to-end evaluation, hard constraints, human review, and repeated trials; slides 6–17 and 26–32 | Evaluate complete user outcomes, not only friendly text |

The teaching example is a resume assistant. Inova adapts the principles to commitments, quests, rewards, and memory. The curriculum's example provider and API calls are not a selected or currently verified implementation for this project.

## What demonstrates agentic behavior

A student asks for help with a busy day. The companion retrieves relevant commitments and approved feedback, asks about missing constraints, proposes a small quest, validates the proposal, and records it only when accepted. A later check-in updates progress and can inform future suggestions.

A trace should show requested capabilities, input references, tool outcomes, validation results, and the final application state. Hidden model reasoning is unnecessary.

## Evidence of quality

Start with ordinary checks for source validity, known scheduling conflicts, duplicate rewards, schema validity, and user permissions. Review usefulness and tone with people. Repeat difficult model-dependent cases because a single successful demonstration is insufficient evidence of reliability.

Lesson 6 was not supplied. No separate final-project rubric, deadline, or judging criteria has been provided beyond the team's theme Evolve.
